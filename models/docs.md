# Витрины интернет-магазина

Здесь собраны витрины для аналитики по данным интернет-магазина.

Данные лежат в хранилище Greenplum. Сырые таблицы магазина загружаются в схему `raw`,
а dbt строит из них три слоя:

- **staging** — сырые таблицы приводятся в порядок: понятные названия колонок, нужные типы.
  Ничего не соединяется и не считается.
- **intermediate** — здесь происходит вся основная работа: платежи собираются по заказам,
  разворачивается дерево категорий, считаются покупки клиентов.
- **marts** — готовые витрины, по которым можно считать отчёты. Это два факта
  (`fct_orders`, `fct_order_items`) и три измерения (`dim_customers`, `dim_products`, `dim_dates`).

Витрины сделаны по схеме «звезда»: в центре факты, вокруг них измерения.
По ним можно посчитать выручку по месяцам и категориям, средний чек по городам,
долю покупателей по каналам привлечения и возвраты по брендам.

Самое важное понятие в проекте — подтверждённая покупка. Это заказ в статусе `paid`,
по которому прошла хотя бы одна успешная оплата. Возврат оплатой не считается.
Полное определение лежит в блоке `confirmed_order` и подставляется в описания колонки `is_confirmed`.

При сборке проекта один тест выдаёт предупреждение. Это тест
`assert_confirmed_order_not_overcharged`: он нашёл заказ 113, по которому деньги списали
дважды по 200, хотя сам заказ стоит 200. Это ошибка в данных источника, а не в витринах,
поэтому заказ оставлен как есть, а тест переведён в предупреждение.

{% docs confirmed_order %}

Подтверждённая покупка — это заказ, который действительно оплачен.

Чтобы заказ считался подтверждённым, нужны два условия сразу:

- статус заказа `paid`;
- есть хотя бы одна успешная оплата.

Возврат записан в источнике как успешная операция с отрицательной суммой, и оплатой он не считается.
Заказы со статусами `pending`, `cancelled` и `returned`, а также тестовые заказы
подтверждёнными не бывают никогда.
